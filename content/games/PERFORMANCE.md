# 探索与竞速：持续游玩优化

维护补丁在 `scripts/game_performance.py`，由三个游戏的构建准备脚本应用。上游源码保持原样。

- 三款游戏桌面绘制上限 60 帧，触屏上限 30 帧。物理计算使用累计经过时间，不按显示器刷新率加速。
- 卡丁车暂停停止绘制；持续低帧率降低像素比例；重开时释放残留实例网格的 GPU 缓冲。
- 骑行暂停停止绘制，仍更新暂停菜单。画质降级后保持稳定，取消自动回升造成的反复调整。长局路线记录最多 3600 个样本，超限降低采样密度并保留原时间戳；跳跃回放最多 480 帧。
- 小鱼乐园每帧最多补算 4 个物理步，避免卡顿后大量补算继续加重卡顿；取消画质自动回升。骑行与小鱼的一次性音效结束后主动断开声音节点。

`scripts/test_game_performance.cjs` 使用实际骑行物理模拟一小时，验证录像上限、时间戳和完成/重开行为。浏览器部分验证卡丁车连续重开 8 次后的 GPU 资源、暂停/恢复、骑行暂停菜单与触屏画质上限，以及小鱼满 110 条时的 GPU 资源稳定性。使用软件 WebGL 运行，测试数据通过拦截 API 隔离，不写入学习账号。

卡丁车在此次连续重开测试中保持 365–367 个几何资源、39–40 个纹理，没有逐局增长；小鱼满 110 条场景四次采样均为 121 个几何资源、7 个纹理。三款的暂停均检查实际绘制次数，骑行同时检查计时冻结、暂停菜单与恢复。上述检查用于判断资源和行为是否稳定，不代表真实平板的帧率保证。

骑行构建：先运行 `scripts/prepare_sunbreak.py`，在 `artifacts/sunbreak-build` 中执行类型检查及 Vite 构建，再复制 `dist` 到 `frontend/assets/games/sunbreak`；准备脚本写入游戏的部署路径配置。其他两款使用现有 `build_turbo_kart.py`、`build_fishslop.py`。
