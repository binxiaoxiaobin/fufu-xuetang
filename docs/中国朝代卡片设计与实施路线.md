# 中国朝代卡片：内容、关联与视频设计

版本：2026-10-11 / 第一阶段

### 时间长卷展示更新

朝代入口新增可点击的 S 形年份长线：电脑每行四个节点，手机每行两个节点，按历史顺序交替折返。19个节点标记各时代的起点及完整年代范围，沿线箭头提示阅读方向；节点间距为阅读布局，不代表实际持续时长。并存时代的起点采用其所涵盖政权的最早年份，完整范围及详情时间条解释重叠关系。节点复用原有详情入口、诗词和故事关联，返回时恢复阅读位置与键盘焦点。

已验证电脑节点打开唐朝及返回、手机375像素内容区的19个节点无标签越界和横向溢出。展示截图：artifacts/history/history-s-timeline.jpg。

## 要做成怎样的学习体验

在“学习卡片 → 语文 → 朝代时光轴”中，孩子先认识时间顺序，再选一个时代。详情依次展示年代、时代背景、并存关系、代表事件、人物和相关作品。诗词使用现有诗词阅读器，人物小传和已有故事使用现有故事阅读器。关闭阅读器后仍留在原来的朝代页面，不必重新寻找人物。

主线是中国主要王朝和时期的入门概览，截至1912年。第一版不是历代所有政权、所有帝王或全部事件的百科全书。“代表”是有目的的选编，不能写成“完整历史”。后续沿相同结构扩充，不另建孤立的故事库、诗词库或后台。

## 第一阶段已实现的范围

19张时代卡片、38件代表事件、40位人物；34篇原创白话人物小传；6篇已有故事关联；补充7首经典作品。每位人物至少有一个可打开的作品入口，人物的诗词不是人人都有，没有作品的不能冒充作者或硬凑一首诗。

时代范围：夏、商、西周、东周（春秋战国）、秦、西汉、新、东汉、三国、西晋、东晋与十六国、南北朝、隋、唐、五代十国、宋辽西夏金、元、明、清。

页面采用温暖的博物馆书册风格：米色纸面、青绿文字、金棕年代、原创主题符号封面；人物用姓名印记，避免把想象肖像冒充真实历史人物画像。视频暂未制作，页面不出现无法播放的假按钮。

统一后台入口：`admin.html → 学习卡片 → 朝代时光轴`。可编辑时代介绍、显示年代、起止年份、分组、排序、讨论问题、代表事件、人物、并存时间条和参考资料；可为人物选择平台中的诗词和故事，标注关系，保存或下架。人物小传正文在“绘本故事”中编辑，分类为“历史人物小传”。

目前后台可新增人物、事件和时间条，尚未提供新增朝代和独立诗词的可视化编辑器；主要时代已经预置。新增朝代、完整诗词编辑与更细的资料管理属于下一阶段，不能把这些称为已完成。

## 年代与历史表达标准

1. 前后顺序和同时并存要分开。三国不能画成魏→蜀→吴；辽、宋、西夏、金不能画成依次继承。时间条反映各政权的时间重叠，不表达疆域面积或正统地位。
2. 西晋265年建国与280年灭吴，隋581年建国与589年灭陈，元1271年定国号与1279年灭南宋，清1636年定国号与1644年入关均分别说明。
3. 夏、商早期使用“约”，夏与二里头的关系注明研究边界。采用夏商周常用断代框架；其他参考年表所用先秦传统年代不混入。
4. 东周王室结束与战国时期结束不同；春秋战国是分期。分界存在不同口径，说明采用的口径，不把它写成唯一事实。
5. 南朝宋与两宋区分；南北朝时期起点与北魏建国年份区分。清结束采用1912年退位节点，1911年革命另列。
6. 人物可能跨时期。曹操、曹冲放在东汉；陶渊明注明东晋至刘宋；李清照注明两宋之际；李煜的作者生涯与作品创作年代分开。
7. 历史人物小传、史书记载的轶事、后世流传故事、传统叙事分别标识。磨杵成针、王羲之吃墨、孟母三迁不能包装成逐项确证的现场实录。
8. 诗词关系分为本人作品、后人咏怀、同题材延伸。诸葛亮关联《八阵图》时，明确是唐代杜甫的咏怀，不能把它署名给诸葛亮。
9. 古典原文、本站白话解读、现代图片与音频的权利分别记录。新增诗文使用公有领域古典原文与原创解读；不搬运现代赏析、译文或朗读文件。
10. 不编造原话、童年经历、具体场景、试验次数或确定的创作日期。没有可靠材料时写“不详”或减少叙述。历史评价兼顾成就与代价，不把人物写成单一好坏标签。

## 数据与关联

第一阶段的数据由两个数据库表承载：

| 表 | 用途 | 约束 |
| --- | --- | --- |
| learning_history_periods | 时代基本字段、人物、事件、时间条、资料引用与视频规划文档 | slug唯一；发布状态；顺序；revision并发版本 |
| learning_history_links | 时代人物与现有诗词、故事的关联 | 时代外键；同一人物/作品不重复；保存时核验作品存在与可用 |
| learning_reading_cards（已有） | 诗词原文、解读、配图、音频 | 沿用现有作品ID与阅读器 |
| stories（已有） | 人物小传与其他故事 | 沿用现有故事ID、阅读进度和奖励 |

初期人物与事件嵌入时代文档，避免一次引入十多个管理表。作品关联独立成表，作品编辑后仍指向同一个ID；显示时读取作品当前标题，不保存复制出来的正文。数据库是运行时内容来源，前台重新进入即可看到后台保存的修改。

文件 `content/learning/history-cards.json` 和 `history-stories.json` 是可审阅、可部署的初始版本。启动和导入使用只补缺失内容的方式，不能覆盖后台已修改的历史卡或小传。新增诗词进入现有诗词种子文件，保证重启后仍可见。

API：

- GET `/api/learning/history`：轻量目录，包含搜索所需的人物与事件名称。
- GET `/api/learning/history/{slug}`：发布状态下的详情与当前有效的作品关联。
- GET `/api/admin/history`：管理员完整目录，包含下架内容和版本号。
- GET `/api/admin/history/choices`：可选作品。
- PUT `/api/admin/history/{slug}`：内容管理员保存；核验必填字段、年代、作品、来源、重复关联及版本。

公开接口不可修改内容。管理接口沿用本机限制、管理员会话和角色权限，写操作登记审计。revision冲突返回409，避免两个编辑页面互相覆盖。正文和关联同一事务提交；保存失败不产生半套关系。下架不删除初始内容，后续可恢复。

## 第一阶段内容边界

人物小传是四页知识介绍，当前封面复用所属时代的主题图，不是已经完成逐页绘本插画的故事长篇。古典作品可阅读解读，并通过现有按需语音服务朗读；新增作品未制作独立预录音频。视频规划仅保存制作方式和章节骨架，未声称视频已完成。

资料分两层：年代/分期有机构来源；人物与作品注明史书、诗集或器物线索。现在是经过事实边界整理的入门选编，尚不属于历史专家逐条签署审定的教材。正式对外发布前，应增加独立的专业校审和作品版本核对。

## 下一阶段的具体拆解

### 第二阶段：内容与后台增强

先补足秦汉、唐宋、明清的关键人物与生活主题，按每批3—5个时代推进。每张卡新增内容必须同时提交来源、事件、人物、作品关联与亲子问题，不能只堆砌名字。

重点工作：

- 事件与人物增加稳定实体ID，事件支持多个来源、史料摘录与校审状态。
- 将跨多个时代的人物迁移到独立人物表，时代—人物多对多；同一人物不重复维护简介。
- 增加朝代创建、诗词原文与版本说明编辑、校审草稿与发布预览。
- 为五代、十国、南北朝以及宋辽夏金增加更细的政权卡；标明“主线时期”和“政权实体”两种类型。
- 每批补充5—10篇有充分史料支撑的长篇人物故事；历史小说式写法必须明确“基于史实的文学创作”，对虚构部分单列说明。
- 每张人物小传增加2—4张与正文相匹配的原创插图，逐页确认；不能把不同时代服饰混用。

验收：同一人物跨时代仍只有一个基础档案；修改作品后全部入口同步；未发布素材不能出现在公开卡片；每一项关系都能追溯到内容ID与编辑记录。

### 第三阶段：选三个时代试制视频

先试“秦：统一标准”“唐：诗人看见的时代”“宋辽夏金：同时存在的世界”。这三个题材分别验证器物演示、诗词叙事和并存时间线，样片合格后再扩展。

**视频风格明确采用博物馆纪录短片，不用白板、写字的手或手绘笔迹。**

画面方案：细腻的时代场景插图与轻微景深运动、经过权利核对的器物近景、清晰的时间与关系图、缓慢镜头推进、少量文字字幕。地图仅在有可靠时间与疆域资料时使用；制作示意图必须标明，不能用AI生成的疆域图冒充历史地图。人物重建画面注明艺术想象，不追求“真实录像”的误导效果。

每条视频120—180秒，分5段：从上一时代接入→用器物或生活问题建立兴趣→两个关键事件→人物与作品→转向下一时代。先完成脚本事实核对，再出分镜与风格帧，最后合成旁白、字幕和画面。音乐只用原创或授权素材，音量不能遮盖旁白。

每条视频交付：脚本、史料说明、分镜、素材权利清单、字幕、1080p MP4、封面、时长与章节标记、移动端播放检查。可选720p版本节省流量。视频关联时代ID；完成前不出现播放入口，完成后给出海报与时长，避免自动播放。

验收：没有手绘制作元素；主要年代与卡片一致；旁白、字幕和画面逐句对应；人物服饰、建筑、器物不过度混搭；不把后世文学故事当史实演出；作品署名与关系正确。

### 第四阶段：从观看到理解

提供轻量时间排序、并存政权辨认、诗词作者与人物区分等活动。重点检验理解而非记忆皇帝名单。先不引入排行榜、重复积分激励或新的家长复杂设置。

## 发布与回滚

初始内容的发布工具：`scripts/publish_history_content.py`。它先备份诗词文件及已有历史数据库数据，再作增量写入。备份位于 `artifacts/history/backup-*`。新增历史卡与关系表可以单独停用，原有诗词、故事与科学卡仍使用原接口。

数据初始化需要已有故事/阅读卡表。完整启动次序为：现有数据库与故事初始化→现有诗词初始化→历史人物小传补缺→朝代与关系补缺。重新启动不替换管理员修改；后台正常编辑不需要重启服务。

工程验收包括：所有19张详情可读取；40位人物有有效关联；新增故事与诗词进入原模块；每个作品链接可打开；宋辽夏金/三国/南北朝时间条正确；筛选与搜索；空结果与失效请求；后台保存、版本冲突、权限拒绝与事务回滚；重启保留修改；桌面、平板与手机无横向溢出。
